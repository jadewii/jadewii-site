AI use-case screener, a risk memo with a fixed shape

Python · Claude structured outputs · pydantic schema · six labelled cases and an eval · tap a case to read it

You describe what a company wants to do with AI in plain English. It returns a memo you could bring to a review meeting: risk tier, who is affected, concrete harms, the controls that have to exist before launch, what a human must still decide, and a go or no-go call. The response is parsed against a pydantic schema, so it is validated JSON and not prose that has to be scraped. The board above is the tier rubric from the system prompt with the six test cases sitting where I labelled them.

The schema follows the NIST AI RMF loop: map the context (who is affected, what the system decides on its own, what data it touches), measure the risks (harms with likelihood and severity, a tier with a rationale), manage them (controls with an owner role and a launch-blocking flag, human oversight, disclosure). The system prompt fixes the tier and decision rubric so two runs on similar cases are comparable, and it says to prefer fewer, sharper controls over a checklist.

The expected labels are my judgment, not ground truth. The eval exists to catch two failure modes: the model calling something low risk because the description sounded benign, and the model padding every case to high risk so the output stops meaning anything. Tier within one is reported separately from exact match, because a medium against high disagreement is a conversation and a low against high disagreement is a bug. It screens the description it is given, so a misleading description produces a confident, wrong memo. One of the six cases is my own art business.
