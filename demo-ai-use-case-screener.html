AI use-case screener

Python · Claude API · structured outputs · eval

A pre-deployment risk screen for a proposed AI use case, built on the Claude API with structured outputs. You describe what a company wants to do with AI in plain English. It returns a memo you could bring to a review meeting: risk tier, who is affected, concrete harms, the controls that have to exist before launch, what a human must still decide, and a go / no-go call.

Why I built it

Most companies adopting AI right now do not have anyone whose job is to ask "what happens when this is wrong?" before a pilot goes live. The questions are not hard, but they have to be asked the same way every time, and the answer has to be structured enough to act on. This turns that into a repeatable step with a fixed schema instead of a chat transcript.

The schema follows the NIST AI RMF loop: map the context (who is affected, what the system decides on its own, what data it touches), measure the risks (harms with likelihood and severity, a tier with a rationale), manage them (controls with an owner role and a launch-blocking flag, human oversight, disclosure).

How it works

  • screen.py sends the use case to claude-opus-5 with messages.parse and a Pydantic schema, so the response is validated JSON, not prose that has to be scraped.
  • The system prompt fixes the tier and decision rubric so two runs on similar cases are comparable.
  • eval.py runs every case in cases/ and compares the model's tier and decision with expected labels written in each file's front matter. Runs are saved to runs/ so re-scoring costs nothing.

The cases

Six use cases with expected labels, from an internal meeting summarizer (low, go) to an unsupervised SMS symptom triage bot (high, no go). One of them is my own business: selling physical art made with open-weight image models and third-party LoRAs of unknown training data.

What the eval is for

The expected labels are my judgment, not ground truth. The point of the eval is not a score. It is to catch the two failure modes that matter for a tool like this: the model calling something low risk because the description sounded benign, and the model padding every case to high risk so the output stops meaning anything. Tier within one is reported separately from exact match because a medium vs. high disagreement is a conversation, and a low vs. high disagreement is a bug.

Limits

  • It screens the description it is given. A misleading description produces a confident, wrong memo. That is a property of every review process, and the tool does not fix it.
  • It is not legal advice and does not know your jurisdiction unless you put it in the description.
  • Six cases is enough to catch gross errors, not to make claims about accuracy.

#!/usr/bin/env python3
"""AI use-case screener: a pre-deployment risk screen for a proposed AI use case.

Give it a plain-English description of something a company wants to do with AI.
It returns a structured screen: risk tier, who is affected, concrete harms,
the controls that would have to exist before launch, what a human must still
decide, and a go / no-go call. The structure follows the NIST AI RMF loop
(Map the context, Measure the risks, Manage with controls) so the output can
drop straight into a review meeting instead of being a chat transcript.

    python3 screen.py cases/refund-chatbot.md
    python3 screen.py --text "We want to ..." --save runs/my-case.json

Needs ANTHROPIC_API_KEY (or an `ant auth login` profile) in the environment.
"""
import argparse, json, pathlib, sys
from typing import List, Literal

import anthropic
from pydantic import BaseModel, Field

MODEL = "claude-opus-5"

RiskTier = Literal["low", "medium", "high", "unacceptable"]
Decision = Literal["go", "go_with_controls", "needs_review", "no_go"]
Level = Literal["low", "medium", "high"]


class Harm(BaseModel):
    description: str = Field(description="One concrete thing that could go wrong, in plain words")
    who_is_harmed: str
    likelihood: Level
    severity: Level


class Control(BaseModel):
    name: str
    why: str = Field(description="Which harm this control addresses")
    owner_role: str = Field(description="Job role accountable for it, not a person")
    before_launch: bool = Field(description="True if launch should block on this control")


class Screen(BaseModel):
    use_case_summary: str = Field(description="Two sentences, what the system does and for whom")
    affected_parties: List[str]
    decision_rights: str = Field(description="What the AI decides on its own vs. what it only suggests")
    data_used: List[str] = Field(description="Personal, proprietary, or regulated data involved")
    harms: List[Harm]
    risk_tier: RiskTier
    risk_rationale: str = Field(description="Why this tier and not the one above or below it")
    required_controls: List[Control]
    human_oversight: str = Field(description="Where a person must stay in the loop, and what they see")
    disclosure_required: bool = Field(description="Must affected people be told AI is involved")
    decision: Decision
    open_questions: List[str] = Field(description="What the reviewer still needs to find out")


SYSTEM = """You screen proposed AI use cases before deployment for a mid-sized company.
You are the person who has to sign the memo, so be concrete and specific to this use case.
Do not pad. Do not list generic risks that do not apply here.

Risk tiers:
- low: internal, reversible, no decisions about people, no regulated data.
- medium: customer-facing or uses personal data, but errors are recoverable and a person reviews outcomes.
- high: the system influences decisions about people's money, health, employment, housing, legal status, or safety, or errors are hard to reverse.
- unacceptable: the use case should not proceed in this form regardless of controls.

Decisions:
- go: launch as described.
- go_with_controls: launch only once the before_launch controls exist.
- needs_review: cannot decide without answers to the open questions; say what they are.
- no_go: do not launch in this form; say what would have to change.

Name controls that could actually be built and owned. Prefer fewer, sharper controls over a checklist."""


def screen(text: str, client: anthropic.Anthropic | None = None) -> Screen:
    client = client or anthropic.Anthropic()
    response = client.messages.parse(
        model=MODEL,
        max_tokens=16000,
        system=SYSTEM,
        messages=[{"role": "user", "content": f"Proposed AI use case:\n\n{text}"}],
        output_format=Screen,
    )
    if response.stop_reason == "refusal":
        raise RuntimeError("model declined to screen this use case")
    return response.parsed_output


def render(s: Screen) -> str:
    lines = [f"RISK: {s.risk_tier.upper()}    DECISION: {s.decision}", "",
             s.use_case_summary, "",
             f"Affected: {', '.join(s.affected_parties)}",
             f"Decision rights: {s.decision_rights}",
             f"Data: {', '.join(s.data_used) or 'none stated'}", "",
             "Harms:"]
    for h in s.harms:
        lines.append(f"  - [{h.likelihood}/{h.severity}] {h.description}  ({h.who_is_harmed})")
    lines += ["", f"Why this tier: {s.risk_rationale}", "", "Controls:"]
    for c in s.required_controls:
        gate = "BLOCKS LAUNCH" if c.before_launch else "after launch"
        lines.append(f"  - {c.name} [{gate}, owner: {c.owner_role}]: {c.why}")
    lines += ["", f"Human oversight: {s.human_oversight}",
              f"Disclosure required: {'yes' if s.disclosure_required else 'no'}"]
    if s.open_questions:
        lines += ["", "Open questions:"] + [f"  - {q}" for q in s.open_questions]
    return "\n".join(lines)


def load_case(path: pathlib.Path) -> str:
    """Case files are markdown with an optional '---' front-matter block of expected labels."""
    raw = path.read_text()
    if raw.startswith("---"):
        _, _, rest = raw.split("---", 2)
        return rest.strip()
    return raw.strip()


def main(argv=None):
    ap = argparse.ArgumentParser(description=__doc__.split("\n")[0])
    src = ap.add_mutually_exclusive_group(required=True)
    src.add_argument("case", nargs="?", help="path to a case .md file")
    src.add_argument("--text", help="use case description inline")
    ap.add_argument("--save", help="write the structured result to this JSON path")
    ap.add_argument("--json", action="store_true", help="print JSON instead of the memo")
    args = ap.parse_args(argv)

    text = args.text if args.text else load_case(pathlib.Path(args.case))
    result = screen(text)
    if args.save:
        p = pathlib.Path(args.save); p.parent.mkdir(parents=True, exist_ok=True)
        p.write_text(result.model_dump_json(indent=2))
    print(result.model_dump_json(indent=2) if args.json else render(result))


if __name__ == "__main__":
    sys.exit(main())
