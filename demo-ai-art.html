AI Art Studio, a prompt library and the request it builds

Python over InvokeAI · 1,317 prompt cards · 96 LoRAs · the studio's own card shelf, pick one and read the exact request it would send





The studio is a Python server over InvokeAI: type a sentence, pick a base model and a stack of LoRA styles, get art. The prompts are mine, six GPT chats cleaned into a 1,317-card library, and they are the input, not the point. The point is the pipeline around them: the request is assembled by a written rule, styles are validated before they load, and the output is gated before it reaches a model file or a circuit board. Three rules in the code do the prompt engineering. The user's sentence goes first so the styles' tokens never bury it, and each picked style appends only its trigger word and its suffix. Character LoRAs publish forty or more trained words, so the server keeps the activation token and drops the list. A style is refused if its LoRA was trained for another base, weights are clamped to 0 to 2, and the LoRAs are chained one loader node per style in the order picked.


Reviewing the library for this page found a bug the cleaning pass left behind: 123 of 1,317 bodies start mid-word ("Ng a Sacred Garden", "Rystals and Ethereal Light") because the step that stripped repeated titles cut a fixed number of characters instead of matching the title. A 30-line check against the system dictionary, promptcheck.py, finds them; it did not exist when the library shipped, and the fix is to re-pull the six chats and run the cleaner with a real prefix match. It is on this page because that is the job: the corpus, the rule, the gate, and the eval you wish you had written first.
